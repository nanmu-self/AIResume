## AIResume 项目梳理与重构方案

对 AIResume（纯前端 Vue3 + Vite + TS + Ant Design Vue简历生成器）做了完整代码梳理，产出 `docs/REFACTOR_PLAN.md`。

### 项目现状
- 技术栈：Vue 3.5 + Vite 6 + TS 5.7 + Ant Design Vue 4 + Pinia 3
- 数据全在 localStorage（`resumeData` / `currentId` / `isFirstVisit`）
- AI 链路：组件 → WorkerPool(4线程) → Cloudflare Worker 反代 → 阿里百炼qwen-turbo
- 4 个模板（templateA/B/C/D）+ dev 脚手架，通过 `import.meta.glob` 构建期扫描加载

### 定位到的 6 个结构性问题
1. `workerPool.ts` 的 `onmessage` 双赋值（14行 vs 62行），首次回调失效
2. `aiWorker.ts:38` SSE 按`\n` 切分未处理跨 chunk 半包，会丢字
3. 模板系统构建期硬编码，`templates.json` 与 glob 结果可能不一致；`config.json` 从未被读取
4. 模板无 props 契约，内部直接 `useResumeStore()`，导致 PDF 导出时 `createApp` 未装 pinia
5. `useSettingsStore` 的 `persist: true` 导致 API Key 明文落盘
6. AI 输出靠 ` ```resume ``` ` 正则约定解析，横跨三个功能且无统一管理

### 重构方案取向
- 四层架构：前端应用 / API 网关 / 领域服务 / 数据与基础设施
- 模板从「构建期组件」改为「运行时数据」，推荐 JSON 驱动方案起步，保留沙箱渲染迁移口
- AI 调用收归服务端，密钥不再下发前端；结构化输出改用 tool call

### Temporal 坑（Prisma 8 + Node 22 的组合问题）
Prisma 8 的 timestamptz 用 Temporal codec，而 Temporal 是 Node 24+ 全局对象，连环报两个错：
1. 读：`Codec ... cannot decode a value because this runtime has no global Temporal implementation`
2. 写：`Codec ... encodes a Temporal.Instant, but received a Date`

**三个关键点**：
1. `temporal-polyfill` 只导出 `Temporal`，**不写 globalThis**，必须显式赋值
2. **不能靠「main.ts 里 import 后再赋值」**——SWC 编译成 CJS 会把 import 提升为顶部 require，赋值排在 Prisma 加载之后，来不及。必须独立成模块靠副作用 import，且验证方法是看 `dist/main.js` 里 `require("./temporal-polyfill")` 是否排第一
3. TS 5.8 lib 没有 Temporal 全局类型，要自己声明最小结构类型
4. `Temporal.Instant.from(date)` 不能直接吃 Date（报 Cannot parse），必须 `fromEpochMilliseconds(date.getTime())`
5. `prisma/seed.ts` 独立于 Nest 容器跑，顶部也要 import polyfill

**产出**：`src/temporal-polyfill.ts` + `src/common/instant.ts`（`nowInstant()` / `toInstant()` / `instantToIso()`），service 层不再出现 `new Date()`。

### 踩坑（重要，浪费了大量时间）

**1. 排查绕了远路：服务跑着旧产物**
模板测试 2 项失败，我误判成代码问题，去查 Prisma 层、写探针脚本、改 DTO——
实际是**改完源码只 build 没重启服务**。杀掉进程用新产物重启就全过了。
已把排查顺序写进 skill：先 `grep 新字段 dist/*.js` 确认产物里有，
有但行为没变就是服务没重启，不要怀疑代码。

**2. ValidationPipe 的 forbidNonWhitelisted 与 @IsOptional**
脚手架开了 `whitelist + forbidNonWhitelisted`，`@IsOptional()` 字段在请求体里
没传时会报 400（嵌套对象里尤其明显）。解法：
- 枚举类字段给默认值（variant/layout/column/visible/status）
- **但 sidebar / page / palette / typography 这类对象字段不能给默认值** ——
  空对象会被灌进 jsonb，渲染器对「字段缺失」和「空对象」应走同一默认路径

**3. visible 该用 IsBoolean 而非 IsInt**
schema 里是 JSON true/false，`@Type(() => Number)` 会把 true 转成 1，语义不符。

**4. tsup 会生成临时配置文件** `tsup.config.bundled_*.mjs`，误入 git，已加 gitignore。

### 模板选择页的设计决策
**预览不用运营上传的静态 preview_url，而是用用户自己的简历数据实时渲染**：
- 静态图与用户内容无关，看不出「换模板后我的简历会怎样」
- 静态图会与实际渲染漂移
- 渲染器是纯函数组件，前端预览与服务端 PDF 导出走同一份代码

缩放用 `transform: scale` 而非 `zoom`（zoom 换算各浏览器不一致，且破坏 fixed 定位）。

### 三个真 bug（都靠实测发现，编译期看不出来）
1. **`choices[0].delta` 少读一层嵌套** —— 流能通、usage 帧也收到，
   但一条 delta 都没有（usage 在 chunk 顶层不经过 choices，
   所以它的存在极具误导性）。类型定义把 choices 元素写成
   `{ content? }`，实际是 `{ index, delta: {...}, finish_reason }`
2. **controller 没消费 `frames` 字段** —— service 已改成返回完整帧序列，
   controller 那行 `wrapFrames([reply])` 的 python 替换没匹配上
   （注释文字有差异），frames 返回了却没人用
3. **`filter(f => f.type !== 'done')` 把结束信号过滤掉了** ——
   done 帧是前端判断「本轮结束」的依据，漏掉会一直等下去

另外 controller 的 `@Sse()` + `@Post()` 默认返 201，需显式 `@HttpCode(200)`。

### 排查纪律（今天踩了四次）
「改了代码但行为没变」时：**先 `grep 新字段 dist/*.js` 确认产物**，
搜到但行为没变就是服务没跑新产物，别怀疑代码。
一次 `pnpm build && node dist/main.js` 串起来最容易出这个问题——
build 成功但 start 失败（端口占用），build 的成功掩盖了 start 的失败。

### 前端 SSE 客户端：拆成独立文件是必要决定
`readSseStream` 原本和 HTTP 客户端放一起，测它必须先 mock 整个
vite 环境（`import.meta.env` 在 Node 下直接抛错）。拆到
`apps/web/src/lib/sse.ts` 后是纯函数，用 tsx 直接 import 就能测。

三个要点：缓冲残留（`parts.pop()` 留不完整块到下一轮）、
多字节字符（`TextDecoder` 必须 `{ stream: true }`）、
三层 data 兼容（用 `type` 字段探测而非无条件解包——
单层时 `{ data: {...} }` 的 type 是 undefined，会被静默丢弃；
这个 bug 是验证脚本测出来的）。
